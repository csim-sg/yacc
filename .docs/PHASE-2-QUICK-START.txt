🎯 KEY DECISIONS (TL;DR):

1. MESSAGE SEND/RECEIVE
   - Connector interface pattern (loose coupling)
   - Stub connectors in Phase 2, real in Phase 3
   - Status: pending → sent/failed
   - Error details: Stored as JSON

2. RETRY QUEUE (BullMQ + Redis)
   - Already 70% implemented in codebase
   - Exponential backoff: 1m → 5m → 30m (3 attempts)
   - DLQ table for ops review after max retries
   - Worker pattern (background processing)

3. WEBSOCKET EVENTS
   - Service → EventEmitter → Socket Controller
   - Use ADR-012 socket-controllers pattern (approved)
   - Message backlog: 1 hour via Redis TTL
   - Include correlation ID in event envelope

4. ATTACHMENTS (Phase 2)
   - Single file upload to Cloudflare R2
   - Multipart form: POST /conversations/:id/attachments
   - Max 5 MB, allowed types: images + PDFs + text
   - Multiple files deferred to Phase 3

5. ERROR HANDLING
   - IETF Problem Details format (RFC 7807)
   - Structured Pino JSON logging
   - Correlation ID propagation
   - Classification: Validation vs Platform vs Server errors

6. ENDPOINTS & PREFIXES
   - Keep existing: /auth/*, /conversations, /messages
   - No global /api prefix (defer to Phase 2+ if needed)
   - No changes to Phase 1 routing
